# 热点雷达 · AstrBot 插件

在飞书 / QQ / Telegram / Discord 里查各平台实时热榜，并订阅关键词——命中关注词的新标题会主动推送到群里。

## 安装

### 方式一：WebUI 上传（推荐，不用登录服务器）

1. 浏览器打开 AstrBot 管理面板（默认 `http://服务器IP:6185`），登录
2. 左侧「插件」→ 右下角 **＋** → **从文件安装**
3. 把 `astrbot_plugin_hotpulse.zip` 拖进去 → 安装
4. 装完在「已安装」里确认版本 `v1.7.0`，打开插件开关

日志里出现 `hotpulse 插件已加载` 即成功。同名插件会被直接覆盖，**不会**动你的订阅数据（存在 `data/plugin_data/` 下）。

### 方式二：手工拷贝目录

```bash
unzip -o astrbot_plugin_hotpulse.zip -d /tmp/hp
cp -r /tmp/hp/astrbot_plugin_hotpulse/. /opt/AstrBot/data/plugins/astrbot_plugin_hotpulse/
rm -rf /tmp/hp
```

> 注意是 `astrbot_plugin_hotpulse/.`（带 `/.`），这样才能合并覆盖、保留旧文件；
> 不带 `/.` 会变成往里套一层 `astrbot_plugin_hotpulse/astrbot_plugin_hotpulse/`。
> 拷完在 WebUI「插件」页点重载，或者 `docker restart astrbot`。

> 依赖只有 `httpx`，AstrBot 自带，正常不需要额外安装。

## 关键词筛选

想知道“榜上有没有我要的”，用 `搜`。它抓一遍全平台，**在本地过滤**，不额外请求上游：

| 指令 | 说明 |
|---|---|
| `/热点 搜 AI` | 从 6 个平台的整张榜里筛出含 AI 的标题 |
| `/热点 搜 AI 芯片` | 多个词是「或」关系 |
| `/热点 搜 AI=AI,大模型,GPT` | 自己定义同义词组，只写组名也行 |

输出会**把同一件事在不同平台的多条合并成一组**，跨平台数多的排前面（这才是真热）：

```
🔍 搜「AI」· 11-07 10:50
22 组结果，其中 3 组多个平台同时上榜

1. 某地发生4.8级地震 暂无人员伤亡
   [微博 · 头条]
2. 6位草根做AI短剧播放破120亿
   [头条热榜]
3. 大家好，这里是 DeepSeek Harness，正式入驻 B 站！
   [B站热门]
```

排序规则：跨平台数越多越靠前（同一件事被三家同时报道才是真热），其次看**榜内名次**（各家热度单位不同，不能直接比），最后才用热度兜底。

合并用的是字符二元组（bigram）包含度，不装分词和向量库——几十条标题是微秒级。短标题（少于 4 字）不参与合并，否则「官宣」会把整页并成一条。

## 用一句话问（自然语言）

不想记指令，直接说人话就行：

| 你说 | 它做的事 |
|---|---|
| 我想看 AI 相关的热点 | 调插件查全平台，返回当前在榜的 AI 条目 |
| 有没有芯片的消息 | 同上，自动展开同义词（半导体/晶圆/光刻…） |
| 最近有什么新能源汽车的事 | 同上 |

返回的每一组都带**平台和链接**（热榜没有正文，链接是唯一入口），并会提醒模型原样转述——不这么写，模型会把「标题（平台）」重排成纯列表，来源和链接一起丢掉，你说「第 1 条」时它就拿不出任何东西。

原理是插件向 AstrBot 注册了一个 `hot_search` 工具，模型判断该查榜时自己调，不需要你写 `/热点 搜`。

除了工具描述，插件还会在每次 LLM 请求的 system prompt 末尾追加一句硬提示（「用户说想看 X 时必须直接调用 hot_search，不要反问」）——实测弱模型会把「我想看ai」当闲聊反问「想看哪块」，光靠工具描述约束不住。

**两个前提**（不满足会走普通聊天，不会返回榜单）：

1. 插件在 AstrBot 里是打开状态；
2. 当前会话用的**人格/配置里允许函数工具**（AstrBot 的「函数工具」列表里能看到 `hot_search`）。

**模型不调用工具时怎么排查**：

1. 面板里确认「函数工具」列表中存在 `hot_search`；插件刚更新过的话，重启容器（`docker restart astrbot`）让工具重新注册；
2. 换个说法再试（「AI 有什么热点」比「我想看ai」更容易触发）；
3. 还是不行就别指望模型了，直接用 `/热点 搜 ai`，这条是纯代码路径，不经过模型。

回答里如果出现「原样转述」这类字样，是我在工具返回值里加的约束，防止模型自己发挥；不影响你阅读。

### 五条设计约束

1. **匹配是字面包含，但支持同义词组**。直接写 `AI` 会自动展开成一整组（大模型 / GPT / LLM / DeepSeek / OpenAI / Claude / Gemini / AIGC / 智能体 / 算力 / 英伟达 / 多模态 / Agent）；也可以写 `AI=AI,大模型,GPT` 自定义。不做语义理解，所以“完全换了个说法”的仍会漏。
2. **只推「新上榜」，不推「还在榜」**。每轮抓到的标题会存成榜单快照，下一轮做差集；一直挂在热搜上的那条不会每半小时提醒你一次。
3. **同一标题只推一次**。掉榜又回来、或者服务重启，都不会重复推（已推记录保留 7 天、最多 3000 条）。
4. **断档不补推**。快照超过 3 个扫描周期没更新（重启、断网、改配置），这一轮只重建快照不推送——否则隔了半天回来，整张榜都会被当成「新上榜」。
5. **默认 23:00–07:00 不抓不推**，避免半夜吵人，早上也不会补推积压。你手动发 `/热点监控 关键词` 触发的即时扫描不受静默时段限制。

后台每 30 分钟扫一轮（可在配置里调，最小 5 分钟），每轮最多推 10 条。订阅数据与榜单快照存在 `data/plugin_data/astrbot_plugin_hotpulse/subscriptions.json`——放在插件目录外面，从 WebUI 重装/升级插件不会被清掉。

## 定时总结（日报）

即时提醒容易被刷屏，所以再加一条「到点汇总」：每天固定时间推一次，先给一段整体概括，再列条目。

```
📊 热点总结 · 11-07 09:00

💭 今天 AI 圈主要在聊三件事：模型厂商拼推理成本、AI 短剧的内容生意，以及芯片供应。

1. 骗子用AI一天做几十条美女视频引流
   百度热搜 · 头条热榜
   https://...
2. 日媒反思为何中国不断诞生AI大模型
   头条热榜 · 742.6万
   https://...
…另有 13 组，发 /热点 搜 关键词 看全榜

· 每天 09:00、21:00 推一次，可在插件配置的 digest_time 调整
· 💭 = AI 根据标题概括，不是原文
```

- 时间在 `digest_time` 里配，24 小时制，多个用逗号分隔（`09:00,21:00`），**留空即关闭**。
- 每轮最多列 `digest_limit` 条（默认 8），前面的概括由 `digest_ai` 控制，关掉就只列条目。
- **同一个时间点只会推一次**，记录写在 `data/plugin_data/.../subscriptions.json` 里，重启不会重复发。
- 到点时榜上没有命中项就**不发**（不刷「今天没消息」这种空消息），但这一档仍记为已处理。
- 和即时推送互不影响：即时推送只在「新上榜」时响，总结按点来。

> ⚠️ **时区**：时间按 AstrBot 进程所在时区算。容器默认通常是 UTC，那么配 `09:00` 实际是北京时间 17:00。
> 先确认：`docker exec astrbot date`。如果是 UTC，在 `docker-compose.yml` 里给 astrbot 服务加 `TZ: Asia/Shanghai` 再重启。

## 云服务器比价

问「阿里云和腾讯云同规格谁便宜、差多少」，用 `/云价`：

```
💰 云服务器比价 · 2核4G 包年

阿里云  1,234.00 元/1年（原价 1,800.00，省 31%）
腾讯云    980.00 元/1年

→ 腾讯云便宜 254.00 元（20.6%）

口径：官方目录价 + 官方折扣，不含限时活动价、代金券、学生优惠。
活动价以官网活动页和下单页为准，这里只做同规格横向对比。
· 换规格：/云价 2核4G、/云价 4核8G
```

也可以定时推：`cloud_time` 设为 `09:10`，每天自动发一份。

### 为什么是「问接口」而不是「抓活动页」

我试过抓活动页，三条路都不通，这是实测结果不是猜测：

| 尝试 | 结果 |
|---|---|
| 抓活动页可见文本 | 能抓，但价格和配置在不同 DOM 节点，抽成纯文本后断开 |
| 「同句含价格 + 规格」正则 | 阿里云/腾讯云/华为云三站合计只命中 **1 条** |
| 找活动页背后的 JSON 接口 | HTML 里没有任何商品/价格接口，卡片由 JS 渲染 |
| 官方价格页（ECS/CVM） | SPA，可见文本 86 / 89 字 |

所以走官方询价 API：`DescribePrice`（阿里云）、`InquiryPriceRunInstances`（腾讯云）。
**代价是拿不到活动价**——99 元/年那种是营销价，接口不返回。这一点写在推送里，不藏着。

### 密钥怎么给（重要）

**不要发给别人，只填在插件配置里**（`secret` 类型，WebUI 遮罩显示）。两家都建议用**子账号**，只给只读权限，不要用主账号 AK：

| 厂商 | 配置项 | 最小权限 |
|---|---|---|
| 阿里云 | `aliyun_ak` / `aliyun_sk` | `AliyunECSReadOnlyAccess`（询价属于只读） |
| 腾讯云 | `tencent_secret_id` / `tencent_secret_key` | `QcloudCVMReadOnlyAccess` |

华为云的询价接口对个人账号不友好，暂不支持。只填一家也能用，只是没有对比、只有单价。

### 规格为什么只有 2核4G / 4核8G

避开了两台都可能缺货的型号：阿里云用 `ecs.c7.large`（2核4G）/ `ecs.c7.xlarge`（4核8G），腾讯云用 `S5.MEDIUM4` / `S5.LARGE8`，都是 1:2 的标准型。2核2G 在腾讯云标准型里没有对应型号，硬凑会拿 1核2G 去比，没意义。

### 排错

| 报错 | 含义 |
|---|---|
| `InvalidAccessKeyId.NotFound` / `AuthFailure` | 密钥填错或没开权限 |
| `InvalidInstanceType` / `UnsupportedOperation` | 该地域不卖这个型号，换地域 |
| `AuthFailure.SignatureFailure` | 腾讯云签名不对——先跑测试确认 `pytest -q` 里那两条签名用例过不过 |

## AI 一句话解读

推送里每条标题下面那行 `💭` 是 AI 写的，用 AstrBot **当前正在使用的模型**，不需要另配 key。

```
1. 骗子用AI一天做几十条美女视频引流
   百度热搜 · 头条热榜 · 296.5万
   💭 说的是有人用 AI 批量生成视频给自己的账号导流
   https://m.baidu.com/s?word=...
```

必须把边界说清楚，因为它决定了这东西能不能信：

1. **它一句话讲完，30 字以内**，方便扫读；**不是新闻原文，是模型看着标题说的话。** 提示词里明确禁止补数字、人名、时间、结论，但模型仍可能推断过头，所以消息末尾固定带一句「💭 = AI 根据标题推测，不是原文」。
2. **只推 10 条就只问 10 条，一次推送只调一次模型**，10 条标题一起喂，2C2G 也扛得住。
3. **模型挂了不影响推送**：超时 30 秒、抛异常、返回格式不对，都只是少掉 💭 这几行，消息照发。
4. **B站不叠加**：B站热榜自带视频简介，那是作者写的原文，有它就不再用 AI 解读。
5. 不想要就在插件配置里把 `ai_brief` 关掉，只留标题 + 链接。

## 配置项

在 WebUI 插件配置页可改：

| 配置 | 默认 | 说明 |
|---|---|---|
| `default_sources` | `weibo,baidu,toutiao` | 不指定平台时查哪些 |
| `default_limit` | `5` | 每平台默认条数 |
| `cache_ttl` | `300` | 缓存秒数，越小越实时 |
| `monitor_keywords` | 空 | 初始关注词，只在本地还没订阅时导入一次 |
| `monitor_interval` | `1800` | 监控扫描间隔（秒），最小 300 |
| `ai_brief` | `true` | 推送里给每条加一句 AI 解读 |
| `digest_time` | `09:00` | 定时总结时间，`HH:MM`，逗号分隔多个，留空关闭 |
| `digest_limit` | `8` | 总结里最多列几条（1-15） |
| `digest_ai` | `true` | 总结开头加一段 AI 概括 |
| `cloud_enabled` | `false` | 开启云服务器比价 |
| `cloud_time` | `09:10` | 比价推送时间，留空不推 |
| `cloud_spec` | `2核4G` | 默认比价规格 |
| `aliyun_ak` / `aliyun_sk` | 空 | 阿里云询价密钥（建议子账号只读） |
| `tencent_secret_id` / `tencent_secret_key` | 空 | 腾讯云询价密钥（建议子账号只读） |
| `quiet_start` | `23` | 静默开始小时 |
| `quiet_end` | `7` | 静默结束小时（与开始相同表示不静默） |
| `weibo_cookie` | 空 | 部分服务器 IP 不填会返回空 |
| `zhihu_cookie` | 空 | **不填则知乎平台不可用** |

### 关于 Cookie

- **知乎**：2026 年起接口强制登录校验，无 Cookie 必然 401。不填时知乎显示在「本次不可用」里，不影响其他平台。
- **微博**：多数 IP 免 Cookie 可用；若返回空数据，浏览器登录微博 → F12 → Network → 复制请求头里的 `Cookie` 值。

Cookie 属于敏感信息，配置项已标记为 `secret`，WebUI 里遮罩显示。

## 飞书接入要点

不需要公网 IP、不需要备案、不需要开放端口 —— 用 AstrBot 的 **socket 长连接**方式订阅事件即可（webhook 模式才需要公网服务器）。

1. [飞书开放平台](https://open.feishu.cn/app) 创建企业自建应用，添加「机器人」能力
2. 拿到 `app_id` / `app_secret`，填到 AstrBot 的 lark 适配器
3. 事件与回调 → 选择「使用长连接接收事件」
4. 添加事件「接收消息」，开通权限 `im:message`、`im:message:send_as_bot`
5. 创建版本并发布，在飞书 App 里找到机器人开聊

群聊里默认需要 @ 机器人 才会响应，这是飞书群的行为，不是插件问题。

```
├── _conf_schema.json    # 配置项定义
├── requirements.txt     # 空文件（无额外依赖，避免安装时触发 pip）
└── core/                # 自包含抓取核心，不依赖 AstrBot
    ├── fetcher.py       # 并发、降级、缓存单飞、失败负缓存
    ├── match.py         # 关键词同义词组、标题 bigram 聚类（搜索与监控共用）
    ├── monitor.py       # 订阅存储、榜单快照比对、关键词匹配、去重
    ├── models.py        # dataclass 数据模型
    ├── settings.py      # 运行期配置与日志注入
    └── sources/         # 6 个平台适配器
```

`core/` 是独立的一层：只用 httpx 和标准库，不知道 AstrBot 的存在，因此可以脱离插件单独测试或复用到别处。

## 已知限制

- **只有标题，没有正文**。热榜接口本身不返回正文；实测抓详情页也被挡：36氪 返回「火山引擎安全检测」，头条要求执行 JS，可见文本分别只有 56 / 26 字。B站是唯一例外（热榜接口自带视频简介）。所以 AI 解读只能停留在标题层面，想核对细节必须点链接。
- 上游接口随时改版，某个平台失败会提示「本次不可用」，改对应 `core/sources/*.py` 的解析即可。
- 知乎依赖 Cookie，过期后需重新填写。
- 关键词是字面匹配，同义表达需要自己补齐。
