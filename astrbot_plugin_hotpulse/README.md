# 热点雷达 · AstrBot 插件

在飞书 / QQ / Telegram / Discord 里查各平台实时热榜，并订阅关键词——命中关注词的新标题会主动推送到群里。

## 安装（两步）

**1. 把整个 `astrbot_plugin_hotpulse` 目录放到 AstrBot 的插件目录**

```bash
cp -r astrbot_plugin_hotpulse /opt/AstrBot/data/plugins/
```

或者用打包好的 zip（注意先解压到临时目录再拷贝，避免多套一层目录）：

```bash
unzip -o astrbot_plugin_hotpulse.zip -d /tmp/hp
cp -r /tmp/hp/astrbot_plugin_hotpulse /opt/AstrBot/data/plugins/
rm -rf /tmp/hp
```

**2. 在 AstrBot WebUI 的「插件」页点刷新（重载插件）**

插件卡片出现「热点雷达 v1.1.0」即成功。日志里会打印 `hotpulse 插件已加载`。

> 依赖只有 `httpx`，AstrBot 自带，正常不需要额外安装。

## 关键词监控

关注某个主题，新上榜的命中标题会自动推到当前会话。

| 指令 | 说明 |
|---|---|
| `/热点监控 AI` | 加一个词，立刻扫一次 |
| `/热点监控 AI,大模型,GPT` | 一次加多个（逗号/顿号/空格都行） |
| `/热点监控列表` | 看当前状态与所有关注词 |
| `/热点监控删除 AI` | 删词 |
| `/热点监控清空` | 清空全部 |
| `/热点监控关闭` / `/热点监控开启` | 暂停 / 恢复 |

推送示例：

```
🎯 热点命中 · 11-07 10:32

【头条热榜】美股收盘：AI概念股止跌反弹
【36氪热榜】一夜变天，奥特曼刚改名「Ram」，芯片股全崩 AI 基建踩刹车
　…
…另有 5 条命中，发 /热点 查看

调整：/热点监控列表
```

### 四条设计约束

1. **只匹配标题里字面出现的词**，不做语义理解。所以“AI 新闻但标题没写 AI”的会漏——建议把同义词一起加：
   `AI, 大模型, GPT, LLM, DeepSeek, OpenAI, 智能体, 算力, 英伟达, AIGC, 多模态`
2. **同一标题只推一次**。热搜挂三小时也只推一次，已推记录保留 7 天（最多 3000 条）。
3. **默认 23:00–07:00 不抓不推**，避免半夜吵人，早上也不会补推积压。
4. **每轮最多推 10 条**，超出的提示「另有 N 条命中」。

后台每 30 分钟扫一轮（可在配置里调，最小 5 分钟）。订阅数据存在插件目录下的 `data/subscriptions.json`，重启不丢。

## 配置项

在 WebUI 插件配置页可改：

| 配置 | 默认 | 说明 |
|---|---|---|
| `default_sources` | `weibo,baidu,toutiao` | 不指定平台时查哪些 |
| `default_limit` | `5` | 每平台默认条数 |
| `cache_ttl` | `300` | 缓存秒数，越小越实时 |
| `monitor_keywords` | 空 | 初始关注词，只在本地还没订阅时导入一次 |
| `monitor_interval` | `1800` | 监控扫描间隔（秒），最小 300 |
| `quiet_start` | `23` | 静默开始小时 |
| `quiet_end` | `7` | 静默结束小时（与开始相同表示不静默） |
| `weibo_cookie` | 空 | 部分服务器 IP 不填会返回空 |
| `zhihu_cookie` | 空 | **不填则知乎平台不可用** |

### 关于 Cookie

- **知乎**：2026 年起接口强制登录校验，无 Cookie 必然 401。不填时知乎显示在「本次不可用」里，不影响其他平台。
- **微博**：多数 IP 免 Cookie 可用；若返回空数据，浏览器登录微博 → F12 → Network → 复制请求头里的 `Cookie` 值。

Cookie 属于敏感信息，配置项已标记为 `secret`，WebUI 里遮罩显示。

## 飞书接入要点

不需要公网 IP、不需要备案、不需要开放端口 —— 用 AstrBot 的 **socket 长连接**方式订阅事件即可（webhook 模式才需要公网服务器）。

1. [飞书开放平台](https://open.feishu.cn/app) 创建企业自建应用，添加「机器人」能力
2. 拿到 `app_id` / `app_secret`，填到 AstrBot 的 lark 适配器
3. 事件与回调 → 选择「使用长连接接收事件」
4. 添加事件「接收消息」，开通权限 `im:message`、`im:message:send_as_bot`
5. 创建版本并发布，在飞书 App 里找到机器人开聊

群聊里默认需要 @ 机器人 才会响应，这是飞书群的行为，不是插件问题。

## 结构

```
astrbot_plugin_hotpulse/
├── main.py              # 插件入口：命令注册、参数解析、监控调度、消息渲染
├── metadata.yaml        # 插件元数据
├── _conf_schema.json    # 配置项定义
├── requirements.txt     # 依赖（仅 httpx）
├── data/                # 运行时生成：subscriptions.json
└── core/                # 自包含抓取核心，不依赖 AstrBot
    ├── fetcher.py       # 并发、降级、缓存单飞、失败负缓存
    ├── monitor.py       # 订阅存储、关键词匹配、去重
    ├── models.py        # dataclass 数据模型
    ├── settings.py      # 运行期配置与日志注入
    └── sources/         # 6 个平台适配器
```

`core/` 是独立的一层：只用 httpx 和标准库，不知道 AstrBot 的存在，因此可以脱离插件单独测试或复用到别处。

## 已知限制

- **只有标题，没有正文**。热榜接口本身不返回正文，正文由各站 JS 动态渲染，HTML 里抓不到。B站是唯一例外（自带视频简介）。
- 上游接口随时改版，某个平台失败会提示「本次不可用」，改对应 `core/sources/*.py` 的解析即可。
- 知乎依赖 Cookie，过期后需重新填写。
- 关键词是字面匹配，同义表达需要自己补齐。
